# 🛡️ NORA — Voice Deepfake Detection

> **Detecting what a synthetic voice tries to hide.**

NORA is a low-latency voice security system created for the **HackMTY26 Altur Challenge: Defend the Bank Against Voice Deepfakes**.

It analyzes banking phone calls and estimates whether the incoming caller is a real human or a synthetic voice generated by AI.

---

## 🚨 The Problem

Voice used to be considered proof of identity. Today, voice-cloning tools can reproduce a person's voice using only a few seconds of audio.

This creates a serious risk for banks and contact centers. Attackers can use synthetic voices to:

- 👤 Impersonate customers
- 🏦 Pretend to represent a bank
- 🔑 Attempt account takeovers
- 💳 Authorize fraudulent transactions
- 🎭 Manipulate agents through social engineering
- 🔐 Obtain sensitive information

NORA adds an additional security layer by analyzing not only **how the caller sounds**, but also **how they behave during the conversation**.

---

## 💡 Our Solution

NORA combines multiple explainable signals instead of relying exclusively on a generic audio classifier.

### 💬 1. Conversational Behavior

NORA analyzes how the caller interacts with the bank's AI agent:

- ⏱️ Response latency
- 📊 Variation in response timing
- 🗣️ Caller interruptions
- 🤖 Agent interruptions
- 🔀 Overlapping speech
- ⏳ Persistence after an interruption
- 🔁 Number of speaking turns
- 🎙️ Caller-to-agent speech ratio
- 💭 Short responses and backchannels

Humans usually react to silence and interruptions with natural irregularity. Automated voice pipelines often respond with more consistent or mechanical timing.

### 🎧 2. Acoustic Characteristics

NORA analyzes the caller's voice for patterns such as:

- ⚡ Energy variation
- 🌊 Spectral flatness
- 🎵 Pitch variation
- 📈 Jitter-like irregularities
- 🔉 Background noise during silence

These measurements can reveal audio that is unusually clean, repetitive, stable, or consistent with generated speech.

### 📝 3. Optional Speech-Pattern Analysis

An experimental version can use **ElevenLabs Scribe v2** to transcribe the caller channel and calculate:

- Filler-word frequency
- Lexical diversity
- Speaking-rate variability

These features complement the acoustic and conversational analysis.

The default model does **not** require an external API, allowing the main endpoint to remain fast and available without depending on an internet connection.

## ⚙️ How It Works

```text
Stereo WAV call
       │
       ▼
Base64 decoding
       │
       ▼
Channel separation
       │
       ├── Channel 0: incoming caller
       └── Channel 1: bank AI agent
       │
       ▼
WebRTC Voice Activity Detection
       │
       ▼
Conversational + acoustic features
       │
       ├── Optional transcript features
       ▼
Logistic regression classifier
       │
       ▼
Synthetic probability and verdict
```

The model is intentionally lightweight and explainable, making it suitable for low-latency telephone environments.

## 🌐 API Endpoint

NORA exposes the HTTP endpoint required by the Altur evaluation system:

```http
POST /detect
Content-Type: application/json
```

### 📥 Request

```json
{
  "call_id": "call_example_001",
  "audio_base64": "BASE64_ENCODED_WAV",
  "sample_rate": 8000,
  "channels": 2
}
```

### 🎙️ Audio Requirements

- WAV format
- Stereo audio
- 8 kHz sample rate
- Channel 0: incoming caller
- Channel 1: bank AI agent

### 📤 Response

```json
{
  "is_synthetic": true,
  "confidence": 0.87
}
```

The `confidence` value represents the estimated probability that the caller is synthetic:

- 👤 Values close to `0`: probably human
- 🤖 Values close to `1`: probably synthetic

```bash
git clone https://github.com/picafresaa/HackMTY26.git

```

### 2. Create a virtual environment

```bash
python3 -m venv venv
```


```text
http://127.0.0.1:8000/detect
```

## ✨ Why NORA Is Different

Many voice deepfake detectors examine only the waveform. NORA also considers the structure of the conversation.

A synthetic caller is often part of an automated pipeline that must:

- Detect when the agent stops speaking
- Decide when to answer
- React to interruptions
- Handle overlapping speech
- Maintain consistent response timing

These behavioral patterns can provide useful evidence even when the generated voice sounds highly realistic.

### NORA's Main Advantages

- 🔍 Explainable features
- ⚡ Lightweight and low-latency classification
- 🖥️ No GPU requirement
- ☎️ Native support for 8 kHz telephone audio
- 🎙️ Independent analysis of both call channels
- 🌐 Optional external transcription
- 🛡️ Designed as an additional banking security layer
- 🔌 Simple JSON-based integration

## 🔐 Proposed Banking Security Protocol

A high-risk result could activate a secondary security workflow:

1. 🚩 Flag the call as suspicious.
2. ⛔ Temporarily prevent sensitive transactions.
3. 🔑 Request additional identity verification.
4. 🕵️ Notify the fraud-prevention team.
5. 🗂️ Save the result and confidence score.
6. 📲 Notify the customer through a verified channel.

NORA is designed to provide a **risk signal**, not to permanently block a customer's account based on a single prediction.

## ⚠️ Current Limitations

- Performance depends on the diversity of the training dataset.
- Transcript-based features add API cost and network latency.
- Confidence is a risk estimate, not absolute proof.
- Unseen voice-generation engines may behave differently.
- Production deployment would require authentication, encryption, privacy controls, monitoring, and periodic retraining.
